## 한 줄 정의

CRM 없는 50명 미만 회사의 영업·마케팅 팀장이 **매일 아침 구글시트 하나를 연결해 열면**, 오늘 연락할 리드 10건과 놓칠 뻔한 리드가 근거와 함께 나온다. 카드를 누르면 첫 메일 초안이 생기고, 연락한 뒤 짧은 메모를 적으면 상담 요약이 담당자에게 이메일로 간다.

## 누구를 위한 것인가

- **사람**: CRM을 도입하지 않은 50명 미만 B2B 기업의 영업·마케팅 팀장
- **상황**: 명함, 세미나·전시회 리드(행사 1회 30~100건), 웹 인바운드가 매주 누적된다. 리드는 구글시트·엑셀에 흩어져 있고, 누구에게 먼저 연락할지 매일 감으로 정한다.
- **근거**: 기존 SDR 인터뷰 3건과 웹 정보. **이 세그먼트에 해당하는 사람을 직접 인터뷰하지는 않았다.** 발표에서 "가설 기반 페르소나"라고 밝힌다.

## 사용 흐름

1. 팀장이 아침에 서비스를 연다. 연결된 구글시트에서 리드를 읽는다.
2. 같은 사람(이메일·전화번호 기준)은 한 카드로 합친다.
3. 맨 위에 **미연락 경고**: 데모·문의 리드가 2영업일 넘게 연락되지 않은 경우.
4. 그 아래 **Top 10**: 점수 순. 카드마다 근거 태그가 붙는다.
5. 카드를 누르면 **첫 메일 초안**이 생긴다. 사용한 근거가 옆에 표시된다. 발송은 팀장이 직접 한다.
6. 연락한 뒤 **[연락함]**을 누르고 100자 내외 메모를 적는다.
7. 시트에 팔로업 Y와 연락일, 상담 요약이 기록되고, 같은 요약이 담당자에게 이메일로 간다.

## 만드는 것

### 데이터 원장

- **구글시트 하나.** 웹폼 리드와 팔로업 Y/N도 이 시트에 쌓인다.
- 서비스는 시트를 읽고, [연락함]을 누를 때 시트에 쓴다. 팀장이 시트에 직접 Y를 적어도 다음 새로고침에 반영된다.
- `설정` 탭: 담당자 이메일, 직급 사전, 가중치 기본값.

### 우선순위 점수 (규칙 기반 + 근거 태그)

| 신호 | 기준 | 근거 태그 예 |
|---|---|---|
| 인입 유형·온도 | 데모·견적 문의 > 웹 문의 > 세미나 참석 > 명함 | `데모 요청` |
| 경과일 | 들어온 지 오래될수록 가점 (놓치기 전에) | `3일 경과` |
| 회사 적합도 | 매출·영업이익률이 높을수록 가점. **정보가 없으면 중립 점수** | `매출 상위` / `재무정보 없음` |
| 직급·역할 | 높을수록 가점. 규칙 사전 4단계(대표·임원 > 팀장·부장 > 과장·차장 > 실무자). **매칭이 안 되면 중간 점수** | `팀장급` / `직급 확인 필요` |
| 소식·이력 | 최근 공시, 여러 채널 유입, 과거 접촉 | `최근 공시` / `3개 채널 유입` |

- LLM은 점수를 매기지 않는다. 순위가 "왜 이 순서인지" 태그로 설명돼야 한다.

### 소식

- DART 공시와 회사 홈페이지 (손영훈 기업조사 로직 재사용). LLM으로 가공하지 않은 원문 링크를 함께 둔다.

### 첫 메일 초안

- 카드를 누를 때만 생성한다. Top 10 전체를 미리 만들지 않는다.
- 시트 정보와 수집한 소식 중 **출처가 있는 사실만** 쓴다. 근거가 없는 문장은 통째로 뺀다.
- 존댓말 격식체 한국어.

### 상담 요약과 인계

- 팀장이 100자 내외로 메모를 적는다. 예: `예산 1천, 12월 도입 검토, 데모 희망`
- LLM이 **니즈 / 예산 / 시기 / 다음 액션** 양식으로 정리한다. 메모에 없는 항목은 `미확인`.
- 요약을 시트에 기록하고 `설정` 탭의 담당자 이메일로 보낸다.
- 통화 녹음·STT는 쓰지 않는다. (인터뷰 2명이 한국어 음성인식의 숫자·제품명 오류로 실망했다.)

### 형태

- **Streamlit 하나.** 기존 프로토타입의 JS 로직은 Python으로 옮긴다.

## 우선순위

| 우선순위 | 항목 |
|---|---|
| **P0** | 구글시트 읽기와 쓰기 (Y/N, 연락일, 상담 요약) |
| **P0** | 중복 합치기 (홍하경 규칙 엔진 재사용) |
| **P0** | 규칙 점수와 근거 태그, Top 10, 미연락 경고 |
| **P0** | DART·홈페이지 소식 |
| **P0** | 카드 클릭 시 첫 메일 초안 (근거만 사용, 출처 표시) |
| **P0** | 100자 메모 → 상담 요약 → 시트 기록과 이메일 인계 |
| P1 | 뉴스 검색, Slack·카카오워크 인계, 가중치 조정 화면 |
| P1 | 후속 메일 시퀀스·답장 분류 (한민수 기능) |
| P2 | S3·Supabase 등 다른 데이터 소스, 통화 녹음 STT |

**일정이 밀리면 내리는 순서**: ① 이메일 인계 → 시트 기록만 ② 상담 요약 LLM 정리 → 메모 그대로 기록 ③ 소식 → DART만.

## 범위 밖

- 메일 자동 발송, 후속 시퀀스, 답장 분류
- 별도 "진행 중" 화면 (시트의 상담 요약 컬럼으로 대신한다)
- 구글시트 외 데이터 소스
- CRM 연동

## 검증 (내부 시연)

외부 사용자 검증 없이 팀원 4명이 시연한다. 외부 검증이 없다는 점은 한계로 밝힌다.

1. 같은 샘플 리드 100건 이상으로 **수작업 vs 서비스**의 Top 10 선정 시간을 잰다.
2. 팀원 4명이 각자 손으로 고른 Top 10과 서비스 결과의 **일치율**을 잰다.
3. 초안과 상담 요약에 **근거 없는 문장이 0건**인지 확인한다.

## 기존 프로토타입 재사용

| 팀원 | 기존 기능 | 통합 서비스에서 |
|---|---|---|
| 손영훈 | 기업조사 (Chrome 확장) | DART·홈페이지 소식, 재무 정보 |
| 홍하경 | 중복 걸러내기 (Streamlit) | 중복 합치기, 회사명·전화번호 정규화, 앱 뼈대 |
| 김이서 | 접촉 이력 통합 요약 | 과거 이력 신호, 출처 표시 방식 |
| 한민수 | 메일 후속 대응 | 메일 템플릿과 수신거부 문구. 후속 시퀀스는 P1 |

담당 분담은 아직 정하지 않았다.

## 아직 정하지 못한 것

- 점수 가중치 숫자
- 샘플 데이터 (100건 이상, 중복·직급 표기 다양성 포함)를 누가 만드는가
