## 누구를 위한 것인가

- **사람**: SaaS·AI 솔루션을 파는 중소기업 영업팀의 SDR (`docs/PROJECT.md` 기준 1~2년차 SDR 관리자·팀장)
- **문제가 나타나는 순간**: 박람회·웨비나·구매 리스트 같은 새 리드 리스트를 받아, 이번 주에 연락할 대상을 고르기 직전. 지금은 이미 연락한 사람이 섞여 있는지 스프레드시트나 CRM 메모를 손으로 대조한다.

## 사용 흐름

1. 새 리드 리스트와 과거 접촉 이력, 두 파일(CSV·엑셀)을 준비한다.
2. 화면에서 두 파일을 올린다.
3. 차단 기준 기간을 확인한다. 기본값은 90일이고, 필요하면 바꾼다.
4. `판정`·`이유`·`겹친 기록` 컬럼이 붙은 결과 엑셀을 받는다.
5. 엑셀에서 판정으로 필터한다. **차단**은 연락 대상에서 뺀다. **확인 필요**와 **주의**는 이유와 겹친 기록을 보고 남길지·뺄지·합칠지 정한다.
6. **신규**와 남기기로 한 행에서 이번 주 연락 대상을 고른다.

## 만드는 것

- SDR이 단독으로 쓰는 도구다. 다른 기능의 한 단계가 아니다.
- 입력: 새 리드 리스트와 과거 접촉 이력, 두 파일 (CSV·엑셀).
- 확인 범위: 새 리스트 안의 중복, 그리고 과거 이력과의 중복. 이력 대조가 핵심이다.
- 출력: 원본 파일에 `판정`·`이유`·`겹친 기록` 컬럼 3개를 붙인 엑셀.
- 화면: 파일을 올리고 받는 화면 하나뿐이다.

## 판정 규칙

| 판정 | 기준 |
|---|---|
| **차단** | 정리한 이메일이나 전화번호가 같음 + 최근 90일 안에 연락함 |
| **확인 필요** | 이름과 회사는 같은데 이메일·전화가 다름 |
| **주의** | 같은 회사의 다른 사람, 또는 90일보다 오래된 접촉 이력이 있음 |
| **신규** | 위 어디에도 해당 안 됨 |

- 정리 방식: 이메일은 대소문자와 공백을 정리한다. 전화번호는 `010-1234-5678`, `01012345678`, `+82 10…`을 모두 같은 번호로 본다.
- 같은 회사 판단: 회사 이메일 도메인(gmail·naver·daum 같은 개인 메일은 제외)과 법인 표기를 정리한 회사명((주)·주식회사·Inc.·Co., Ltd. 제거, 띄어쓰기 무시)으로 **규칙 기반** 판단한다.
- 규칙으로 판단이 안 되는 한글·영문 표기 차이(예: 토스 / Toss / 비바리퍼블리카)만 LLM에 맡기고, 결과에 **"AI 추정"**이라고 표시한다. 규칙으로 판단한 결과는 **"규칙 일치"**로 표시한다.
- 90일 기준은 SDR이 바꿀 수 있다. 90일이 맞는지는 실제 SDR에게 확인한다.
- 자동 삭제나 자동 합치기는 하지 않는다. 남길지·뺄지·합칠지는 SDR이 정한다.
- 개인정보는 외부로 보내지 않는다. LLM에는 회사명만 보내고, 이름·이메일·전화는 내 컴퓨터 안에서만 비교한다.

## P1 AI 모델과 실패 처리

- **모델**: Claude Haiku 5.5 (`claude-haiku-5-5`). 회사명 두 개가 같은 회사인지 판단하는 짧은 작업이라 빠르고 저렴한 모델로 충분하다.
- **실패할 때** (오류, 시간 초과, 애매한 답): 그 행은 규칙 결과만 쓰고, 판정을 **확인 필요**로 올린다. `이유`에는 "AI 판단 실패 — 규칙 결과만 사용"이라고 적는다. 놓친 중복을 가장 중요하게 보기로 했으니, AI가 판단하지 못한 행은 SDR이 직접 보게 한다.

## 검증

- 평가 세트의 정답은 규칙을 만들지 않은 사람이 결과를 보기 전에 붙인다. 실제 SDR이 붙이고, 안 되면 한민수 님이 붙인다.
- 개발에 쓴 데이터는 평가에 쓰지 않는다.
- 지표:
  1. 놓친 중복 수 (가장 중요)
  2. 잘못 차단한 수
  3. 리드 100건 처리 시간: 수작업과 비교하되, 도구 쪽은 SDR이 결과를 검토하는 시간까지 포함한다.
- 같은 평가 세트를 엑셀 '중복 항목 제거'와 ChatGPT로도 처리해서 세 결과를 한 표로 비교한다.
