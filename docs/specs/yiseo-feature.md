## 누구를 위한 것인가

- **사람**: SaaS·AI 솔루션을 파는 중소기업 영업팀의 SDR (`docs/PROJECT.md` 기준)
- **문제가 나타나는 순간**: 이벤트·파트너사로부터 **행사 다음 날 대량 리드 CSV를 받아 처리할 때**. 지금은 CRM, Slack, 이메일을 손으로 뒤져 각 리드가 기존 접촉 이력이 있는지 확인하고, 중복 연락 여부를 판단한 뒤, 팔로업 우선순위를 스프레드시트에 정리한다.
- **인터뷰 근거**:
  - 중복 연락 실수가 가장 흔한 실수다 — 3명 중 3명
  - 접촉 이력이 CRM·Slack·이메일에 흩어져 있어 한눈에 파악하기 어렵다 — 3명 중 2명

## WhyTree 노드

- 주된 why: **접촉 이력 통합 요약** → 리드 데이터 관리 → 어카운트 기회 전환

## 형태

- **Pure HTML/CSS/JS 단일 페이지.** `index.html`을 브라우저에서 직접 열어 쓴다. 서버·번들러 없음.
- 설정 파일(`config.js`)에 Gemini API 키를 넣는다. 키는 `.gitignore`에 등록되어 저장소에 올라가지 않는다.

## 사용 흐름

1. SDR이 `index.html`을 연다.
2. 이벤트·파트너사에서 받은 리드 CSV를 업로드한다.
3. 에이전트가 각 리드를 3개의 접촉 이력 소스와 대조한다.
4. 결과 목록을 본다. 각 리드 행마다:
   - **이력 없음**: "이전 접촉 없음" 표시, LLM 문장 없음.
   - **확정 중복** (이메일 일치): 이력 요약과 함께 "같은 사람 / 다른 사람" 선택지가 나타난다.
   - **의심 중복** (이름+회사 일치, 이메일 없음): 동일하게 선택지가 나타나되, "의심" 배지가 붙는다.
5. 각 리드에 레이블을 붙인다: **follow_up / skip / reassign**.
6. 처리가 끝나면 결과 CSV를 내려받는다.

## 만드는 것

### 입력 리드 CSV 스키마

| 컬럼 | 필수 여부 |
|---|---|
| `lead_name` | 필수 |
| `lead_email` | 선택 (없으면 이름+회사 매칭만 시도) |
| `company` | 필수 |
| `title` | 선택 |
| `event_name` | 선택 |
| `event_date` | 선택 |

### 접촉 이력 소스 (3개, 모두 fixture CSV)

각 소스 파일에는 `source_id` 컬럼이 있다. 요약 문장에 출처를 표시할 때 이 값을 쓴다.

**CRM 활동 CSV**

| 컬럼 | 설명 |
|---|---|
| `contact_email` | 매칭 키 (이메일) |
| `contact_name` | 매칭 키 (이름, 이메일 없을 때) |
| `company` | 매칭 키 (회사, 이메일 없을 때) |
| `date` | 접촉 일자 |
| `channel` | email / call / meeting |
| `rep_name` | 담당 SDR 이름 |
| `outcome_note` | 결과 메모 |
| `source_id` | 예: `crm-001` |

**Slack 발췌 CSV**

| 컬럼 | 설명 |
|---|---|
| `date` | 메시지 날짜 |
| `sender_name` | 발신자 |
| `recipient_email` | 선택. 없으면 이름+회사로만 매칭 → 의심 |
| `customer_name` | 고객 이름 (이메일 없을 때 매칭 키) |
| `company` | 고객 회사 (이메일 없을 때 매칭 키) |
| `message_text` | Slack 메시지 본문 발췌 |
| `source_id` | 예: `slack-001` |

**이메일 스레드 CSV**

| 컬럼 | 설명 |
|---|---|
| `date` | 발송 날짜 |
| `from_email` | 발신 이메일 |
| `to_email` | 수신 이메일 |
| `subject` | 제목 |
| `body_snippet` | 본문 발췌 |
| `source_id` | 예: `email-001` |

### 매칭 로직

1. **이메일 매칭 (확정)**: `lead_email`이 소스의 이메일 컬럼과 정확히 일치하면 확정 중복.
2. **이름+회사 매칭 (의심)**: 이메일이 없거나 이메일 매칭 결과가 없을 때, 이름과 회사명을 정규화해 비교. 일치하면 의심 중복.
3. **한국 회사명 정규화**: `(주)`, `주식회사`, `㈜`를 앞뒤에서 제거하고 공백을 정리한 뒤 비교한다. 예: `(주)카카오`, `주식회사 카카오`, `카카오` → 모두 `카카오`로 취급.
4. **매칭 없음**: 신규 리드.

### 중복 처리 UI

확정·의심 중복이 발견된 리드는 카드를 펼쳐 보여준다:
- **왼쪽**: 입력 CSV의 신규 리드 정보
- **오른쪽**: 매칭된 이력 행 목록 (날짜, 채널, 담당자, 메모, `source_id`)
- **버튼**: 같은 사람 / 다른 사람
  - "같은 사람" 선택 시 → `match_status = confirmed_duplicate` 또는 `suspected_duplicate` 유지, 레이블 선택으로 진행
  - "다른 사람" 선택 시 → `match_status = new`로 전환, 레이블 선택으로 진행
- CRM에 쓰지 않는다. 결정은 내보내기 CSV에만 기록된다.

### 내보내기 CSV

모든 행을 포함한다 (skip 포함). 원본 컬럼 전부 + 아래 추가 컬럼:

| 추가 컬럼 | 설명 |
|---|---|
| `disposition` | follow_up / skip / reassign |
| `match_status` | new / confirmed_duplicate / suspected_duplicate |
| `prior_history_summary` | LLM 문장 또는 구조화된 필드 텍스트 |
| `source_ids` | 기여한 source_id를 쉼표로 구분한 문자열. 이력 없으면 빈 값. |

### 설정 파일

- `config.js`: `GEMINI_API_KEY`를 담는다. **`.gitignore`에 등록.** 저장소에 올라가지 않는다.
- `config.example.js`: 키 값을 빈 문자열로 둔 예시 파일. 커밋한다.
- `.gitignore`에 반드시 포함: `config.js`, `.env`, `node_modules/`

## AI 모델과 실패 처리

- **모델**: Google **Gemini 2.5 Flash** (무료 한도). 접촉 이력 한 줄 요약에만 쓴다.

### LLM 규칙

- 매칭된 이력이 **1건 이상** 있을 때만 LLM을 호출한다. 이력이 없으면 LLM을 호출하지 않는다.
- LLM에게는 **매칭된 행만** 전달한다. 리드의 직함·예산·타이밍을 추론하거나 지어내지 않는다.
- LLM이 출력한 문장 옆에 **`source_ids`를 괄호로 표시**한다. 예: `"3개월 전 박민수가 가격 문의를 받았으나 후속 일정이 잡히지 않았다. (crm-003, slack-007)"`
- **지어내지 않는 항목**: 예산, 타이밍, 직함. 이 정보가 매칭된 행에 없으면 언급하지 않는다.

### 실패 시 동작

| 실패 상황 | 동작 |
|---|---|
| API 키가 `config.js`에 없음 | LLM 호출 없이 구조화된 필드를 그대로 표시한다. |
| API 호출 실패 (네트워크 오류, 한도 초과, 형식 오류) | 오류 메시지 없이 구조화된 필드를 표시한다. 내보내기는 정상 동작한다. |
| 이력 없는 신규 리드 | "이전 접촉 없음" 표시. LLM을 호출하지 않는다. |

## 직접 해 볼 확인 (수동 테스트)

**테스트 1 — 중복 분류**  
20행짜리 CSV를 만든다. 그중 2행은 이메일이 소스 파일과 일치하는 확정 중복이고, 1행은 이름+회사 매칭이지만 회사명이 `(주)OO`와 `주식회사 OO`로 다르게 표기된 의심 중복이다.  
→ 결과: 확정 중복 2건, 의심 중복 1건이 각각 올바른 배지로 표시된다.

**테스트 2 — 이력 없는 신규 리드**  
소스 파일 어디에도 이메일·이름·회사가 없는 리드 1행을 포함한다.  
→ 결과: "이전 접촉 없음" 텍스트가 표시된다. LLM 문장이 나타나지 않는다. `prior_history_summary`는 "이전 접촉 없음", `source_ids`는 빈 값으로 내보내진다.

**테스트 3 — API 키 없음**  
`config.js`에서 `GEMINI_API_KEY` 값을 지운다(빈 문자열로).  
→ 결과: 이력이 있는 리드에 구조화된 필드(날짜·채널·담당자·메모)가 그대로 표시된다. LLM 문장 없이도 내보내기 CSV가 정상 생성된다.
