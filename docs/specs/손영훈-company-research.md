## 누구를 위한 것인가

- **사람**: SaaS·AI 솔루션을 파는 중소기업 영업팀의 SDR (`docs/PROJECT.md` 기준)
- **문제가 나타나는 순간**: 리드에게 **첫 연락(콜드메일·콜)을 하기 직전**, 그 회사가 무엇을 하는 곳인지 파악할 때. 지금은 회사 홈페이지, 공시, 기사를 손으로 열어 보고 메모한다. 하루 10~20건을 접촉하면 이 조사 시간이 가장 크다.

## WhyTree 노드

- 주된 why: **기업조사 → 시간절약** (실선) → 효율적 리소스 분배
- 부가 why: 기업조사 → **정확도 높은 세일즈** (점선) → 매출 향상

## 형태

- **Chrome 확장 프로그램 + 사이드 패널.** SDR이 회사 사이트나 CRM 웹 화면을 보면서 옆에 결과를 띄워 둔다.
- CRM 애드온은 P2다. 확장 프로그램은 CRM 웹 화면 위에서도 동작한다.

## 사용 흐름

1. SDR이 조사할 회사의 웹사이트를 Chrome에서 연다.
2. 확장 아이콘을 누르면 오른쪽에 사이드 패널이 열린다. **현재 탭 주소가 자동으로 채워진다.** CRM 화면을 보고 있었다면 주소를 고쳐 쓴다.
3. 회사명을 입력하고 **[조사]**를 누른다.
4. DART에서 비슷한 이름의 회사가 여러 개 나오면, 후보 목록(회사명, 종목코드, DART 등록 홈페이지)에서 하나를 고른다.
5. 결과를 본다.
   - **[웹사이트] 섹션**: 한 줄 소개, 제품·서비스, 고객층, 첫 연락 대화 소재 2개. 항목마다 출처 링크.
   - **[DART 공시] 섹션**: 기업개황(대표자, 설립일, 업종 코드, 주소, 홈페이지)과 최근 공시 5건(제목, 날짜, 원문 링크).
6. 대화 소재를 첫 연락 메일이나 콜에 쓴다. 의심되는 항목은 출처 링크를 눌러 확인한다.

## 만드는 것

### 입력

- 웹사이트 주소: 필수. 현재 탭에서 자동으로 채우고, 수정할 수 있다.
- 회사명: DART 검색에 쓴다. 비워 두면 DART 섹션은 건너뛴다.

### 웹사이트 섹션

- 홈 + 홈에서 찾은 **회사 소개·제품 페이지 최대 2개**를 읽는다.
- LLM이 읽은 원문**만** 근거로 한국어로 정리한다. 제품명과 고유명사는 원문 그대로 둔다.
- 항목마다 출처 URL을 붙인다. 출처 URL은 실제로 읽은 페이지 중 하나여야 한다. 아니면 그 항목은 보여 주지 않는다.
- 원문에서 찾지 못한 항목은 "사이트에서 확인되지 않음"으로 표시한다. 지어내지 않는다.
- (구현 후 추가) 자바스크립트로 그려지는 사이트는 서버에서 받은 HTML에 글이 거의 없다. 조사할 주소가 **지금 열린 탭과 같은 페이지**면, 탭 화면에 그려진 글자를 함께 읽어 보완한다. 그래도 글이 200자 미만이면 "사이트를 읽지 못했습니다"로 멈춘다.

### DART 섹션

- 회사명으로 DART 고유번호 목록을 검색한다. 정확히 일치하는 이름과 상장사를 먼저 보여 준다. 후보는 최대 5개.
- (구현 후 추가) DART 고유번호 목록(수 MB)은 처음 한 번 받아 내 Chrome에 30일 동안 저장한다. 설정 화면에서 다시 받을 수 있다.
- 기업개황과 최근 1년 공시 중 최신 5건을 보여 준다. **LLM으로 가공하지 않는다.**
- 웹사이트 정보와 DART 정보가 다르면 **둘 다 나란히** 보여 주고, SDR이 판단한다.
- 대화 소재는 DART 최근 공시(예: 투자 유치)를 근거로 쓸 수 있다. 이때 출처는 공시 원문 링크다.

### 설정 화면

- Gemini API 키와 DART API 키를 입력한다. 키는 **내 Chrome(`chrome.storage.local`) 안에만** 저장된다. 저장소, 코드, 커밋에는 키가 없다.

## AI 모델과 실패했을 때

- **모델**: Google **Gemini 3.8 Flash** (`gemini-3.8-flash`, 무료 한도). 웹사이트 요약과 대화 소재 작성에만 쓴다.
- (구현 후 변경) 처음에는 Gemini 2.5 Flash로 정했지만, 실제 키로 실행하자 "신규 사용자에게 더 이상 제공되지 않는 모델" 오류가 났다. Google 권장 모델인 3.8 Flash로 바꿨다. Gemini 3.x는 temperature 설정을 받지 않으므로 보내지 않는다.
- 무료 한도에서는 Google이 요청 내용을 제품 개선에 쓸 수 있다. 보내는 것은 공개된 회사 웹사이트 글과 DART 공시 제목뿐이다.

| 실패 상황 | 동작 |
|---|---|
| 웹사이트를 읽지 못함 (주소 오류, 차단, 내용 없음) | "사이트를 읽지 못했습니다"와 이유를 보여 주고 웹사이트 섹션을 멈춘다. **LLM 자체 지식으로 채우지 않는다.** |
| LLM 호출 실패 (키 오류, 한도 초과, 응답 형식 오류) 또는 Gemini 키 없음 | 오류 메시지 + 읽어 온 원문 일부(페이지당 600자) + 출처 링크를 보여 준다. |
| LLM이 읽지 않은 URL을 출처로 씀 | 그 항목을 버린다. |
| DART 키 없음, 또는 DART 호출 실패 | DART 섹션에 이유를 보여 주고, 웹사이트 결과는 그대로 보여 준다. |
| DART에 없는 회사 | "DART 공시 대상이 아닌 회사이거나 이름이 다릅니다"를 표시한다. 정상 흐름이다. |

## 우선순위

| 우선순위 | 항목 |
|---|---|
| **P0** | Chrome 확장 + 사이드 패널, 현재 탭 주소 자동 입력 |
| **P0** | 설정 화면 (Gemini 키, DART 키) |
| **P0** | 웹사이트 조사: 홈 + 소개·제품 페이지 최대 2개, 한 줄 소개·제품·고객층·대화 소재 2개, 항목별 출처 |
| **P0** | DART: 회사명 검색과 후보 선택, 기업개황, 최근 공시 5건. (DART 키를 오늘 발급받지 못하면 P1로 내린다.) |
| **P0** | 위 실패 처리 표의 모든 동작 |
| P1 | DART 재무 요약 (매출, 영업이익) |
| P1 | 웹 검색·뉴스 연동, 주소 없이 회사명만으로 조사 |
| P1 | 여러 회사 일괄 처리 (CSV) |
| P2 | CRM 애드온 (Salesforce, HubSpot) |
| P2 | LinkedIn 연동 |
| P2 | CRM에 결과 저장, 메일 자동 발송, 조사 히스토리 |

## 범위 밖 (이번에 하지 않음)

- 여러 회사 일괄 처리, 웹 검색·뉴스, LinkedIn, CRM 저장·애드온, 메일 발송, 조사 히스토리
- 회사 규모·매출을 웹사이트에서 추정하기 (DART 재무는 P1)
- Chrome 웹 스토어 배포 (개발자 모드로 로드해서 쓴다)

## 직접 해 볼 확인 (수동)

1. **상장사 1곳** (DART에 있는 회사): 웹사이트 섹션과 DART 섹션이 모두 나온다. 모든 항목에 출처 링크가 있고, 링크를 눌렀을 때 실제로 그 내용이 있다.
2. **DART에 없는 소규모 SaaS 1곳**: "DART 공시 대상이 아닌 회사"가 표시되고, 웹사이트 결과는 정상으로 나온다.
3. **잘못된 주소** (오타, 없는 사이트): "사이트를 읽지 못했습니다"와 이유가 나오고, 지어낸 내용이 하나도 없다.

시간이 되면 같은 회사를 손으로 조사할 때와 확장으로 조사할 때 걸리는 시간을 재서 기록한다. (시간절약 노드의 근거)
